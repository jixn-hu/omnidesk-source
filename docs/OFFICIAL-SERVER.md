# 可选账号服务

从 0.6.0 起，账号服务与桌面客户端分为两个独立 GitHub 仓库：

- 开源桌面客户端：`jixn-hu/omnidesk-source`（MIT）。
- 账号服务与网页管理后台：独立私有项目，不在本次客户端源码发布中。

本仓库不再包含服务端源码、Dockerfile 或服务端依赖。使用账号功能需自行配置可访问的独立服务；本仓库不提供账号后台部署包。下述管理和迁移说明适用于已有服务的维护者。

## 客户端配置

「账号与同步」中的服务地址默认留空，应用不会自动连接某个账号服务。使用账号功能时自行填写部署好的 HTTPS 地址并保存。已有手动保存的地址保留；清空或更换地址会清除旧账号会话，不会删除本机连接、公共凭据或 WebDAV 设置。

本机开发允许回环 HTTP，远程服务必须 HTTPS。不要将真实部署地址、证书私钥、账号密码或配置库写入源代码。自签名证书首次连接需核对指纹，证书变更时重新确认。

账号功能是可选辅助功能：不注册、不登录也能正常使用本机 SSH、RDP、公共凭据、导入导出、监控和 WebDAV。登录不会自动上传服务器，配置同步仍由用户主动上传 / 拉取。

## 独立管理后台

在部署好的账号服务地址后加 `/admin/`，使用管理员账号登录。

- 新部署默认关闭公开注册；在服务端运行 `npm run admin:create` 或 `docker compose exec account npm run admin:create` 交互创建首个管理员，没有默认密码。已有账号数据不会被初始化命令覆盖。
- 「登录与注册」可即时开关注册，也可配置自建 GitLab Application、Secret、回调地址。关闭注册同时阻止密码注册和 GitLab 首次建号，已有启用用户仍可登录。
- 「用户管理」支持搜索、分页、创建成员、启用 / 停用、角色调整、重置密码、撤销会话和输入账号名确认删除；查看登录、同步与共享状态，不显示用户密码、私钥、令牌或同步密钥。
- 不允许停用、降级或删除当前管理员，至少保留一名启用管理员。停用账号同时阻止密码和 GitLab 登录，修改权限或密码会撤销其会话。

## 共享与同步边界

共享目录仅下载配置副本，不在共享页建立远程会话。下载后在本机正常连接、编辑，服务器流量不经过云端；发布时会确认其他已登录账号可获得选定配置和凭据。按协议和实际入口去重，撤销共享不能收回已下载副本。本机修改后需重新发布才能更新云端条目。

当前配置共享不要求 `OFFICIAL_TARGET_CIDRS` 或 guacd。该环境变量仅保留给历史会话网关兼容路径，不应为配置共享开放整个内网。

个人同步配置仅当前账号可访问，但服务端保管解密密钥，并非零知识存储。上传前检查云端版本；云端有更新时先确认合并，再生成加密快照上传。上传期间遇到版本竞争会重新检查、合并并重试，最多尝试三次；持续竞争会停止上传，保留本机已合并配置。取消合并不会上传；解密失败、网络故障不会通过跳过版本检查强行覆盖。拉取和上传前的合并均保留本机独有连接，同 ID 使用云端内容，不传播删除。

## 从旧的单仓库部署迁移

1. 备份现有数据卷或完整数据目录，必须一起保存 `official.sqlite` 与 `server-master.key`。
2. 在独立服务仓库设置 `OFFICIAL_DATA_VOLUME` 为现有实际数据卷名，或正确挂载原数据目录，不能换成新空卷。
3. 停止写入后切换镜像和 Compose，保留原 HTTPS Origin、证书和 GitLab 回调地址。
4. 访问 `/health` 和 `/admin/`，使用现有管理员登录并检查账号、同步与共享数据。
5. 已持久化的注册设置不会被默认值覆盖；如已有服务开启注册，管理员需在页面明确关闭并保存。

代码上传不等于线上部署。不要执行 `docker compose down -v`，不要丢失主密钥，也不要把真实配置、TLS 私钥或数据库提交到 GitHub。
